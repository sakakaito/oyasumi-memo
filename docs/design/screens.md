## 0. 共通の部品

### 0-1. 話すボタン（S1・S2 の中央）
方式W・方式K のどちらでも同じ見た目・同じ文言で置ける部品。押したあとのふるまいだけが違う。

| | 方式W（Web Speech API） | 方式K（キーボードの音声入力） |
|---|---|---|
| 見た目 | 直径 184px の丸。地 `--n-surface`、文字「タップして話す」20px・太さ 600 | 同じ |
| タップすると | その場で録音を始める（下の「録音中」） | S4 が開き、入力欄にカーソルが入ってキーボードが出る |
| 止め方 | もう一度タップ／無音が続いたら自動（考えごと 10 秒・日記 20 秒、試作値） | 「預ける」／文字が増えなくなって同じ時間がたったら自動 |
| `aria-label` | 待機中「話して預ける」（S1 は「日記を話す」）／録音中「止めて預ける」（S1 は「止めて日記に残す」） | 「入力欄を開く」 |
| `aria-pressed` | 録音中は `true` | 使わない |

- 実装の注意（方式K）：iPhone でキーボードを出すには、タップの処理の中で入力欄に `focus()` する必要がある
- 環境で方式を使い分ける場合（例：Safari のタブは W、ホーム画面アプリは K）も、利用者が方式を選ぶ画面は作らない。使えない方を出さないだけにする

- 保存の知らせ：`--n-text`・16px・`role="status"`。2 秒表示して 1 秒かけて消える

### 0-3. 文字で書く画面（S4）（2026-10-26 フェーズ2で更新）

S2 の「文字で書く」でメモ用、S1 の「文字で書く」で日記用が開く（フェーズ4 からは、エラーのカードの［文字で書く］と方式K の話すボタンからも）。初版の「下から出るシート」をやめ、**夜の画面の中身と差し替える全画面**にした（理由は下の案の比較）。

```

│ 文字で預ける          閉じる │ ← h1（18px）／右上はテキストのボタン（当たり判定 44px）
│ ┌───────────────────────┐ │
│ │思いついた順に、そのまま │ │ ← 入力欄 17px。高さは 4 行ぶんで固定

│ │                         │ │
│ └───────────────────────┘ │
│ （1 行：失敗したときだけ文字）  │ ← 高さは常に 1 行ぶん確保
│ ［        預ける        ］  │ ← 主ボタン 48px・横いっぱい
├───────────────────────────┤
│  キーボード（暗い色）          │ ← 上の全部が、iPhone SE でもキーボードの上に収まる
└───────────────────────────┘
```

#### 置き方の案（キーボードで隠れないようにする）

iPhone の Safari は、キーボードが出てもページの高さを縮めない。画面の下に固定したボタンは、キーボードの裏に隠れる。

| 案 | 中身 | よい点 | 気になる点 |
|---|---|---|---|
| **案1：上に寄せる** ★おすすめ | 見出し・入力欄（4 行で固定）・1 行・主ボタンを画面の上から詰めて置く。合計 約 280px | JavaScript なしで、主ボタンがいつもキーボードのすぐ上に来る（iPhone SE で見える高さ 約 300〜340px に収まる）。キーボードが出ても閉じても何も動かない | 大きい iPhone では、主ボタンとキーボードの間が少し空く。入力欄が 4 行と小さめ |
| 案2：キーボードの真上に貼る | `visualViewport` の高さに合わせて、主ボタンをキーボードの上に貼りつける | 入力欄を大きく取れる。チャットアプリと同じ形 | キーボードが上がり切ってから位置が跳ぶ（夜の画面に動きが出る）。iPhone の版ごとのずれの調整が要る |
| 案3：主ボタンを右上に | iPhone のメモの共有画面のように、右上に［預ける］ | どの機種でも隠れない | 片手の親指で右上は一番届きにくい。キーボードから指を大きく動かす |

- おすすめは案1。夜は「動かない」ことと、親指がキーボードからすぐ届くことを優先した。4 行（全角 約 80 字ぶん）で足りない人は、欄の中でスクロールして書ける
- 高さの見積もり：上の余白 8＋見出しの行 44＋間 8＋入力欄 142（17px × 1.7 × 4 行＋上下の余白 24＋枠 2）＋1 行 27＋主ボタン 48 ＝ 約 277px（＋上の安全領域）

#### iPhone のキーボードを暗くする（`color-scheme: dark`）
- 夜の画面と入力欄の `color-scheme` を **`dark` だけ**にする。`light dark` にすると iPhone の設定（ライト／ダーク）に従い、ライトモードの iPhone では白いキーボードになる
- 置く場所は 3 つ：① `<meta name="color-scheme" content="dark">`（今もある）、② CSS の `:root { color-scheme: dark }`（夜・紹介）と `:root[data-mode="morning"] { color-scheme: light }`、③ 夜の入力欄そのもの `color-scheme: dark`。今は ① の meta を JavaScript で書き換えているだけなので、② ③ を足す（実行中の meta の書き換えだけだと Safari が反映しないことがある）
- キーボードの上に出る「↑ ↓ 完了」の帯も、同じ設定で暗くなる見込み
- **実機で確かめる**（plan フェーズ2 のオーナー確認 5、spec §13）。iPhone を**ライトモードにした状態**でも暗くなるかを必ず見る。暗くならない場合、Web ページからそれ以上は変えられない（最後の「オーナーに決めてほしいこと」）

#### 状態

| 状態 | 見え方・ふるまい |
|---|---|
| 開いたとき | S2（または S1）の中身が S4 に差し替わる（動きなし）。入力欄にカーソルが入り、キーボードが上がる。中身は空か、前に閉じたときの書きかけ（カーソルは末尾）。**前に預けた文は出さない** |
| 入力中 | 何も変わらない。文字数・「保存します」の予告は出さない。入力欄は高さ固定で、あふれたら欄の中でスクロール（欄が伸びる動きを出さない） |
| キーボードを閉じた（下へスワイプ・「完了」） | S4 はそのまま。上に寄せてあるので何も動かない。入力欄をタップすれば、またキーボードが出る |
| 空のまま・空白だけで［預ける］ | 何も保存しない。文言も出さない。入力欄にカーソルを戻す（キーボードが閉じていれば上がる）。主ボタンは `aria-disabled="true"` で、文字 `--text-sub`・枠 `--line` に弱める。`disabled` 属性は使わない（VoiceOver で見つけにくくなり、押しても何も起きない理由が分からないため）。区切りで分けた結果がすべて空（「。。」だけなど）も同じ扱い |
| 保存中 | 二度押しは無視する。見た目は変えない（保存は一瞬なので、回る印などは出さない） |
| 保存できた | キーボードを閉じて、S4 から元の画面（S2／S1）へ戻る。元の画面の状態の表示行に「預かりました」／「日記に残しました」→ 2 秒 → 1 秒で消える。入力欄と書きかけは空にする。フォーカスは S4 を開いたボタン「文字で書く」に戻す。日記なら S1 の右下が「次へ」になる |
| **保存できなかった** | S4 は閉じない。**入力した文字はそのまま**、キーボードもそのまま。状態の 1 行に「**保存できませんでした。文字は残っています**」（`--warn`・16px・`role="alert"`）。自動では消さず、次に主ボタンを押したときに消して、もう一度保存を試す。ほかの文言・エラーのカードは出さない（主ボタンがすぐ下にあるので「もう一度押して」は書かない） |
| 閉じる | 書きかけは、メモ用・日記用で別々に持っておき、次に開くと戻る（閉じても消さない、確認も出さない）。フェーズ2 はページを開いている間だけ（メモリ）でよい。保存に失敗したあとに閉じた場合も同じ |

- 区切りの規則：メモ用から送った文は、句点・改行・「それと」「あと」などで分けて複数のメモにする（US-01 方式K と同じ規則、plan 2-C）。日記用から送った文は分けずに 1 つの日記（2-D）
- 自動保存（フェーズ4、方式K の寝落ち対策）：メモ用は文字が増えなくなって 10 秒で保存して S4 を閉じ「預かりました」。日記用は入力のたびに下書きを保存し、同じ日記に追記していく（日記が分かれない。US-10）。自動保存も「保存できた」と同じ道を通るので、画面は作り直さない

#### エンジニアへの注意（見え方に関わる分だけ）
- iPhone でキーボードを出すには、**タップの処理の中で**入力欄に `focus()` する必要がある。React の状態で S4 に切り替えるなら、`flushSync` で描いてから同じ処理の中で `focus()` する（あとの `useEffect` で `focus()` すると、iPhone ではキーボードが出ない）
- S4 を開いている間・書きかけがある間は、夜／朝の自動の切り替え（`autoSwitch`）で画面を差し替えない。書きかけが消えるため（例：4:59 に書いていて、5:00 過ぎに戻ってきた）
- S4 を開いたときにページをスクロールさせない（`scrollIntoView` などを使わない）。上に寄せてあるので、iPhone は入力欄を見せるためのスクロールをしない見込み

## S0 紹介ページ（検索に出す唯一のページ）

### 狙う検索語と SEO の設定

## フェーズ2 でオーナーに決めてほしいこと（2026-10-26 フェーズ2で更新）

`flow.md` §6 の 1〜3 とは別に、フェーズ2 の画面で決めたいことです。iPhone の確認（plan フェーズ2 のオーナー確認 2〜6）のときに、あわせて見てください。

1. **日記の入口の置き場所（仮）。** 夜の画面（S2）左上の小さな「今日の日記」→ S1 →「文字で書く」の形です（S1 の節の案1）。確認1 が案A でも案B でも、この形のまま使えます。案A なら、あとで「日記を使う人は夜の始まりに S1 を出す」規則を足すだけです。左上の小ささ・位置で、気づけるか・邪魔でないかを見てください。
2. **文字で書く画面の置き方。** 入力欄とボタンを画面の上に寄せ、ボタンがキーボードのすぐ上に来る形（0-3 の案1）にしました。お使いの iPhone で［預ける］がキーボードに隠れないか、入力欄 4 行が狭すぎないかを見てください。狭ければ、キーボードの真上に貼る形（案2）に変えます（夜の画面に少し動きが出ます）。
3. **キーボードが暗くならなかった場合。** iPhone を**ライトモードにしたまま**でもキーボードが暗く出るかを見てください。出ない場合、Web ページの側からはそれ以上変えられません。そのときは「そのまま受け入れる」か「初回案内（S9）でダークモードを勧める 1 文を足す」かを決めたいです。おすすめは、まず実機で見てからです。
