## 0. このファイルの読み方

### 優先度
| 優先度 | 意味 |
|---|---|
| **Must** | 最初の公開（MVP）に必ず入れる。欠けると公開しない |
| **Should** | 価値は高い。MVP の次に入れる。MVP に余裕があれば前倒し |
| **Could** | あるとうれしい。使ってもらった反応を見てから決める |
| **Won't** | 今回はやらない（§1 のスコープ外、または方針と合わない） |

### ID
- US-0x：夜（考えごとを預ける）
- US-1x：日記
- US-2x：朝の振り返り
- US-3x：設定・データ
- US-4x：PWA（ホーム画面アプリ）・初回案内
- US-5x：紹介ページと SEO

### 音声入力の方式（未決）
iPhone 実機の結果待ちのため、受け入れ条件は次の 2 方式のどちらでも成り立つように書く。

| 略号 | 方式 | 中身 |
|---|---|---|
| **方式W** | Web Speech API | アプリのボタンで録音を始め、ブラウザの機能で声を文字にする |
| **方式K** | キーボードの音声入力 | アプリは入力欄を開くだけ。iPhone のキーボードのマイクで話す |

- 各ストーリーの受け入れ条件は「共通」→「方式W のとき」→「方式K のとき」の順に書く
- 環境ごとに方式を使い分けてもよい（例：Safari のタブでは W、ホーム画面アプリでは K）
- どちらの方式でも、テキスト入力欄はいつでも使える（§12）

## 1. プロダクトの一文説明と、解決する困りごと

### 一文説明
**考えごとで眠れない夜に、布団の中で頭の中を声で話して「預けて」眠るための、無料・登録不要の Web アプリ。その日の日記も声で残せる。**

### 誰の、どんな困りごとか
- **誰**：仕事に疲れた 20 代後半〜40 代。主な端末は iPhone（§12）
- **困りごと**：布団に入ってから、明日やること・気になることが頭の中を回って眠れない
- **今の解決のしかた（推測）**：スマホで「考え事 眠れない」と検索する。メモアプリに打つと目が冴える／打つのが面倒

### 根拠（§12 の検索データ、Ahrefs・日本・2026-10-24 時点）
| 検索語 | 月間検索数 | スマホ比率 | 読み取れること |
|---|---|---|---|
| 考え事 眠れない | 800 | 97% | 軸にする語。困りごとそのもので検索している |
| 考えすぎて眠れない | 200（上位ページへの流入は合計 2,400） | 97% | 軸にする語。関連語を含めると需要はもっと大きい |
| 不安で眠れない | 1,100 | 96% | 近い悩み。心の健康に近いので扱いは慎重に（US-52） |
| ブレインダンプ | 1,200 | 71% | 「頭の中を全部書き出す」方法。補助の語 |
| ジャーナリング アプリ | 600 | 86% | 日記まわりの手がかり（意図は未確認） |
| 頭の中 整理 アプリ／寝る前 アプリ | ほぼ 0 | – | **アプリを探して検索する人はほぼいない** |

- スマホ比率 97% → **布団の中で、今まさに眠れずにいる人**が来る。紹介ページを開いたその場で使えることが大事
- 「睡眠 アプリ」（3,100）は数が多いが、睡眠の記録や環境音のアプリを探す人が多いと思われる（未確認）。約束する価値がずれるので、狙わない

### 約束する価値（紹介ページとアプリで一致させる）
1. 文字を打たずに、声で頭の中を下ろせる
2. 下ろしたものは、朝に「やること・気になること・アイデア」に分かれて待っている
3. 中身はこの端末の中だけ。登録もいらない
4. （日記）今日のことを声で話せば、文字の日記として残る

※「眠れるようになる」とは約束しない（治療効果をうたわない。§12）

## 2. 全ストーリー共通の約束

どのストーリーにも次の条件がかかる。個別の受け入れ条件には繰り返し書かない。

- [ ] メモと日記の中身を外部に送らない。アナリティクス（利用状況の計測）も入れない。例外は声を文字にする OS の機能だけ（§1・§8・§12）
- [ ] iPhone の Safari（タブ）とホーム画面アプリの両方で確かめる。次に Android Chrome（§8・§12）
- [ ] 文字は最小 16px。ボタンには `aria-label`（読み上げ用の名前）をつける（§8）
- [ ] 夜の画面では、白・青系の強い色、点滅、動きを使わない（§5-1）
- [ ] 「その夜の日付」（`sleepDate`）は、0:00〜4:59 の入力を前日にする。夜モードの時刻設定と同じ値から計算する（§4・§13）

### 3-1. 夜（考えごとを預ける）

#### US-01 声で考えごとを預ける 〔Must〕
布団の中で考えごとが止まらない人として、文字を打たずに声で頭の中を話して預けたい。なぜなら、打つ作業で目が冴えるし、早く手放して眠りたいから。

受け入れ条件
- 共通
  - [ ] 夜の画面から 1 タップで話し始められる
  - [ ] 話した内容が文字になり、メモとして端末に保存される
  - [ ] 1 回の吹き込みは、内容の区切りごとに 1 件以上のメモになる
  - [ ] 保存したメモは、翌朝の画面（US-20）にその夜の分として出る
- 方式W のとき
  - [ ] タップで開始、もう一度タップで停止（§12。「押している間だけ」は採らない）
  - [ ] 認識結果の区切り（話して間が空いたところ）ごとに 1 件のメモにする（§13）
  - [ ] iPhone では連続モードを使わず、認識が途切れたら自動でつなぎ直す（§12 試作 v2）
  - [ ] 録音中はボタンがほんの少し明るくなるだけ。認識中の文字はごく薄く小さく（§5-1・§13）
- 方式K のとき
  - [ ] 1 タップで入力欄が開き、キーボードが出る（iPhone 実機で確認）
  - [ ] 送った文章を、句点・改行・区切りの言葉（「それと」「あと」など §6）で分けてメモにする。分けられなければ 1 件
  - [ ] キーボードが暗い色で出る（`color-scheme: dark`。§13 の確認項目）

#### US-02 テキストで考えごとを預ける 〔Must〕
声を出せない場面（家族が寝ている等）の人として、文字でも同じように預けたい。なぜなら、声が使えない夜も手放したいから。

受け入れ条件
- [ ] 夜の画面に、いつでもテキスト入力への入り口がある（「フォールバック」扱いにしない。§12）
- [ ] 送った文章は US-01 と同じ規則でメモに分けて保存される
- [ ] 入力欄も夜の配色で、眩しくない

#### US-03 目が冴えない夜の画面 〔Must〕
眠りたい人として、夜の画面で目が冴えないようにしたい。なぜなら、画面の光や情報で余計に眠れなくなるから。

受け入れ条件
- [ ] 背景はほぼ黒、文字は暗めのグレー（色の値はデザイナーが決める。§5-1 の例を基準）
- [ ] 画面中央に大きなボタン 1 つ。件数・時計・ナビゲーションは出さない
- [ ] 夜/朝の切替アイコンは小さく、目立たない（§5-4）
- [ ] 夜の画面から出るエラー表示や案内も、白い画面にならない

#### US-04 「預かりました」で受け取ったとわかる 〔Must〕
預けた人として、ちゃんと受け取られたとわかりたい。なぜなら、確かめるために見返すと目が冴えるから。

受け入れ条件
- [ ] 保存できたら「預かりました」と一言だけ出し、2 秒後に静かに消える（§5-1）
- [ ] 保存の中身（認識した文字）は読ませない
- [ ] 保存に失敗したときは、その旨を一言で伝え、入力した文字は消さずに残す

#### US-05 寝落ちしても話した内容が消えない 〔Must〕
話しながら寝てしまう人として、操作をしなくても話した分が残ってほしい。なぜなら、停止ボタンを押す前に眠ることがあるから。

受け入れ条件
- 共通
  - [ ] 話し終えて何もしなくても、一定時間で自動保存される。時間は考えごと初期 10 秒・日記初期 20 秒（試作値。実機の結果で決める §13）
  - [ ] 画面が消えた・別のアプリに移ったときも、そこまでの内容は保存されている
- 方式W のとき
  - [ ] 無音が上の時間続いたら、録音を止めて保存する（終わったら必ずマイクを手放す）
- 方式K のとき
  - [ ] 文字が増えなくなってから上の時間がたったら、そこまでを保存する
  - [ ] キーボードが閉じても、入力済みの文字は保存される

#### US-06 声が使えないとき、直し方と別の手段がわかる 〔Must〕
音声がうまく動かない人として、何をすればよいかすぐわかりたい。なぜなら、夜中に原因を調べる気力はないから。

受け入れ条件
- 共通
  - [ ] 声が使えないとき、理由に合った直し方を短く出す（夜の配色のまま）
  - [ ] 直せないときは、テキスト入力へ 1 タップで移れる
- 方式W のとき
  - [ ] エラーの種類ごとに iPhone での直し方を出す（例：`service-not-allowed` → 設定 → 一般 → キーボード → 音声入力をオン。§12）
  - [ ] 音声認識が使えない環境（ホーム画面アプリなど）では、キーボードのマイク（方式K）へ案内する
- 方式K のとき
  - [ ] キーボードにマイクが出ないときの設定場所（音声入力のオン）を案内する

#### US-07 「おやすみ」で画面を真っ黒にして終える 〔Could〕（§13 案B）
預け終えた人として、最後に画面を真っ黒にして終えたい。なぜなら、画面を閉じる操作の間も光を浴びたくないから。
- 受け入れ条件は採用が決まってから書く。US-13（夜の流れ）で採るなら Should に上げる

#### US-08 夜の色を暖色寄りにする 〔Could〕（§13 案C）
- デザイナーの検討事項。US-03 の色決めの中で一緒に比べてもらう

### 3-2. 日記（2026-10-25 オーナー追加）

前提（§12）：日記は 1 回の録音（開始から停止まで）を 1 つの日記にまとめる。仕分けはしない。自動保存までの無音は長め（試作 20 秒）。

#### US-10 声で今日の日記を話して残す 〔Must〕
仕事に疲れた人として、寝る前に今日あったことを声で話し、文字の日記として残したい。なぜなら、書くのは面倒だが、1 日を言葉にして閉じたいから（理由は推測。オーナーに合っているか見てほしい）。

受け入れ条件
- 共通
  - [ ] 日記を始める入り口がある（置き場所は §5 の提案と「確認 1」で決める）
  - [ ] 1 回の吹き込みが 1 つの日記になる。区切りで分けず、仕分けもしない（§12）
  - [ ] 日記の日付は `sleepDate` と同じ規則（0:00〜4:59 は前日の日記）
  - [ ] 日記は「全部見た」（US-24）やメモの片付けで消えない。**残すもの**として扱う
  - [ ] 話しているあいだの画面は夜の配色（US-03 と同じ）
- 方式W のとき
  - [ ] 開始から停止まで、途中で認識が途切れても自動でつなぎ直し、1 つの日記につなげる
  - [ ] 無音が日記用の時間（初期 20 秒）続いたら止めて保存する
- 方式K のとき
  - [ ] 入力欄を開いてから保存するまでが 1 つの日記
  - [ ] 途中で自動保存が走っても、同じ日記に追記され、日記が分かれない

#### US-11 テキストでも日記を書ける 〔Must〕
声を出せない夜の人として、日記も文字で書きたい。
- [ ] 日記の入力でも、テキスト入力がいつでも使える
- [ ] 保存のされ方は US-10 と同じ（1 回 = 1 つの日記）

#### US-12 日記を読み返す・直す・消す 〔Must〕
日記を残した人として、あとで読み返し、誤認識を直したい。なぜなら、残すための日記だから。
- [ ] 日記を日付ごとに新しい順で見られる。同じ日に複数あれば時刻順に並ぶ
- [ ] 日記を開いて、文字を直せる
- [ ] 日記を 1 件ずつ消せる（確認つき）
- [ ] 読む画面は明るめで読みやすい（朝の配色）

#### US-13 夜の流れ（日記 → 預ける → おやすみ） 〔Should〕
- 例：①今日の日記（とばせる）→ ②頭の中を預ける → ③おやすみ。§5 の提案と「確認 1」で形を決めてから受け入れ条件を書く
- 決まるまでの MVP では、夜の画面に「日記」の入り口を 1 つ足すだけにする（US-10）

#### US-14 朝の画面で昨夜の日記に気づける 〔Should〕
- [ ] 前夜に日記があるとき、朝の画面に 1 行だけ知らせが出て、タップで開ける
- [ ] 日記の本文は朝の振り返り（US-20）の一覧には混ぜない（30 秒で見終える画面を重くしない）

#### データ構造について（エンジニアへの条件）
- 日記をメモと同じ表に「種類」（`kind: 'memo' | 'diary'`）を足して入れるか、別の表にするかは、エンジニアが決めてよい
- プロダクトとしての条件：エクスポート（US-31）・インポート（US-35）・全削除（US-32）・日付の規則が、メモと日記の両方に同じように効くこと
- MVP の時点で、日記を区別できる形にしておく（後から作り直さないため）

### 3-3. 朝の振り返り

#### US-20 朝、前夜のメモを分類つきで見る 〔Must〕
朝の人として、昨夜預けたものを分類つきでさっと見たい。なぜなら、やることだけ拾えれば、あとは手放してよいから。
- [ ] 朝モードでは、直近の夜（`sleepDate`）のメモが「やること」「気になること」「アイデア」「その他」に分かれて出る（§5-2）
- [ ] 背景は明るめで読みやすい
- [ ] 前夜のメモがないときは、その旨を一言だけ出す

#### US-21 メモが自動で仕分けられている 〔Must〕
- [ ] 保存のとき、キーワード辞書で 4 つに仕分ける。該当なしは「その他」（§6）
- [ ] 辞書は別ファイルで、後から足せる
- [ ] 代表例 10 件以上の単体テストが通る（§6）
- [ ] 仕分けの関数は、将来 AI 版に差し替えられる形（非同期）にする（§10・§13）

#### US-22 誤認識をタップして直す 〔Must〕
- [ ] メモをタップすると文字を直せる（§13「誤認識は朝の画面でタップして直す」）
- [ ] 直しても分類は勝手に変わらない（変えたいときは US-23）

#### US-23 分類の変更・完了・削除 〔Must〕
- [ ] タップで分類を切り替えられる
- [ ] 完了のチェックをつけ外しできる
- [ ] 1 件ずつ削除できる

#### US-24 「全部見た」でまとめて片付ける 〔Must〕
朝の人として、見終わったら一度で片付けたい。なぜなら、残っていると気になるから。
- [ ] 「全部見た」で、表示中のメモをまとめてアーカイブ（見終わった扱い）にする（§5-2）
- [ ] 日記はアーカイブされない（US-10）

#### US-25 「気になること」を手放す 〔Should〕（§13 案A）
- 「気になること」に「まだ気になる？ → もう大丈夫／今日考える」を出し、「完了」と「手放す」を分ける
- コンセプトの核に近いので、MVP の次に最初に入れる候補。受け入れ条件は採用が決まってから書く

#### US-26 過去の夜を日付ごとに見る 〔Should〕
- [ ] アーカイブ済みも含め、過去の夜のメモを日付ごとに見られる（§5-2）

#### US-27 通勤中に片手 30 秒で振り返れる 〔Should〕（§13 案I）
- [ ] 主な操作（完了・全部見た）が親指の届く画面下半分にある
- [ ] 前夜が 10 件程度なら、スクロール少なく見終えられる（件数の目安は未確認。実際の使われ方を見て直す）

#### US-28 終わらなかった「やること」を次の夜に持ち越す 〔Could〕（§13 案E）
- 「手放す」コンセプトと逆向きになりうる。使ってもらった反応を見てから決める

### 3-4. 設定・データ

#### US-30 データの扱いが正確に書いてある 〔Must〕
中身を人に見られたくない人として、メモがどこに保存され、どこに送られるかを正確に知りたい。なぜなら、頭の中をそのまま話すから。
- [ ] 設定画面と紹介ページに、§12 の文言をそのまま載せる
  > メモの内容は、この端末の中にだけ保存されます。声を文字にするときは iPhone（Apple）の音声認識を使うため、話した音声は Apple のサーバーで処理されることがあります。
- [ ] 方式W・方式K のどちらでも正しい内容であること（どちらも Apple の音声認識を使う）
- 提案（了承が出たら条件にする）
  - Android では「Android（Google）の音声認識」に読み替えた文言を出す
  - 「利用状況の計測もしていません」を一文足す

#### US-31 データを書き出す（エクスポート） 〔Must〕
- [ ] メモと日記のすべてを JSON（すべての項目つき）と、人が読めるテキスト（日付ごと、日記とメモを分けて）で書き出せる
- [ ] 書き出しは端末の中で行い、どこにも送らない
- [ ] iPhone で「ファイル」アプリに保存できる、または共有メニューで渡せる（実機で確認）

#### US-32 データを全部消す 〔Must〕
- [ ] メモ・日記・設定をすべて消し、初回の状態に戻る
- [ ] 消す前に確認ダイアログを出す。「元に戻せない」ことを書く（§5-3）

#### US-33 夜／朝を手で切り替える 〔Must〕
- [ ] 起動した時刻で夜/朝の画面が決まる（初期値：18:00〜翌 4:59 が夜。§5-3・§5-4）
- [ ] 画面右上の小さなアイコンで手動で切り替えられる

#### US-34 夜モードになる時刻を変える 〔Should〕
- [ ] 夜の始まりと終わりを変えられる。`sleepDate` の境目も同じ値で動く（§13）

#### US-35 書き出したデータを読み込む（インポート） 〔Should〕
Safari で使い始めてからホーム画面に追加した人・機種変更した人として、前のメモと日記を引き継ぎたい。なぜなら、iPhone では Safari のデータがホーム画面アプリに引き継がれないから（§13 案F の注意）。
- [ ] US-31 の JSON を読み込める。同じものを二重に入れない
- 「確認 2」の答えによっては Must に上げる

#### US-36 保存データを消されにくくする 〔Should〕
- [ ] `navigator.storage.persist()` を使う（§13）
- 補足：Safari では、しばらく開かないサイトのデータが消されることがあり、ホーム画面アプリは対象外と WebKit が公表している（実機での挙動は未確認）。ホーム画面への追加をすすめる理由にもなる（US-42）

#### US-37 自動保存までの時間を変える 〔Could〕
- 実機の結果で初期値を決めたあと、変えたい人が多ければ設定に出す

### 3-5. PWA（ホーム画面アプリ）・初回案内

#### US-40 ホーム画面に追加して使える 〔Must〕

- [ ] アイコン、アプリ名、暗いテーマ色が設定されている。iOS 向けの `apple-touch-icon` などもある（§7）

#### US-41 通信がなくても使える 〔Must〕
- [ ] 一度開いたあとは、機内モードでも開ける。テキストで預ける・朝に見る・日記を読む・設定が使える（§7）
- [ ] 声を文字にする機能は、通信がないと使えない場合がある（方式・端末による。未確認）。使えないときは US-06 の案内でテキストへ移れる

#### US-42 ホーム画面に追加する方法がわかる 〔Should〕

- [ ] 案内の中身は、決まった音声方式に合わせる（方式W がホーム画面アプリで動かない場合は、そこではキーボードのマイクを使うと書く）

#### US-43 初回の案内で、夜に迷わない準備が済む 〔Must〕

- 共通
  - [ ] 初回に、使い方を短く案内する（3 画面以内）。あとから設定画面で見直せる
  - [ ] マイクまわりの準備は、夜ではなく初回の案内か朝モードで済ませる（§13）
- 方式W のとき
  - [ ] マイクの許可は初回の案内の中で取る
  - [ ] **毎晩の吹き込みで、許可のダイアログが出ないこと**（§13 で最重要。実機で確認）。毎回出るなら方式K を本命にする
- 方式K のとき
  - [ ] キーボードのマイクの位置と、音声入力をオンにする設定場所を案内する

#### US-44 アプリが更新されてもデータが消えない 〔Must〕
- [ ] 新しい版を公開しても、端末のメモ・日記・設定はそのまま残る
- [ ] 更新は、夜の画面で突然の再読み込みや白い画面を起こさない

### 3-6. 紹介ページと SEO

狙う検索語：**軸「考え事 眠れない」「考えすぎて眠れない」、補助「ブレインダンプ」**（§12）。

#### US-50 「考え事 眠れない」で来た人が、その場で試せる紹介ページ 〔Must〕
布団の中で「考え事 眠れない」と検索した人として、開いたページで解決のしかたがわかり、そのまま試したい。なぜなら、アプリを探しに来たのではなく、今眠れずに困っているから。
- [ ] 題名・h1・説明文を、実際に検索される言い方に合わせる。案（最終の文言はデザイナーとオーナー）
  - title：考え事で眠れない夜に、頭の中を声で預けるメモ｜おやすみメモ
  - h1：考えすぎて眠れない夜は、頭の中を声で預けて眠る
  - description：考え事が頭から離れず眠れない夜に。布団の中で話すだけで、やること・気になることに分けて朝まで預かります。登録不要・無料、メモは端末の中だけに保存。
- [ ] 中身が題名を裏付ける：①こんな夜に（共感）②使い方 3 ステップ ③頭の中を外に出すとは（ブレインダンプの説明）④データは端末の中だけ（US-30）⑤よくある質問 ⑥眠れない日が続くとき（US-52）
- [ ] 最初の画面に「今夜ここで預ける」ボタンがあり、1 タップで夜の画面が開く
- [ ] **夜に開いても眩しくない配色**にする（来る人の 97% はスマホ、多くは布団の中と考えられる）
- [ ] 治療効果をうたわない。「眠れるようになる」と言い切らない（§12）
- [ ] アプリに無い機能を書かない。日記の扱いは「確認 1」に従う
- 関連：紹介ページとアプリを一体にするか（§13 案F）は「確認 2」

#### US-51 ページの SEO 設定と自動点検 〔Must〕
- [ ] 検索に出すページごとに、固有の `<title>`・meta description・正規 URL（canonical）・OGP（SNS で共有したときの題名・説明・画像）をつける
- [ ] サイト全体に `sitemap.xml` と `robots.txt` を置き、検索に出すページをすべてサイトマップに載せる
- [ ] 構造化データ（JSON-LD：検索エンジン向けにページの中身を説明する書き方）をつける。アプリの紹介（`WebApplication`：名前・無料・対応環境）、FAQ がページにあれば `FAQPage`、階層があればパンくず。**ページに無い内容は入れない**
- [ ] h1 は 1 ページに 1 つ。見出しの階層を飛ばさない。画像には alt（代わりの文）
- [ ] 紹介ページ・関連ページ・アプリの間で内部リンクを張る
- [ ] アプリの画面（夜・朝・設定）と試作ページは、検索に出さない（`noindex`）。ただし「確認 2」で一体型にするならこの条件を見直す
- [ ] 上の抜けを機械的に見つける点検スクリプトをビルドに組み込み、抜けがあればビルドを失敗させる
- [ ] 正規 URL は本番の公開先が決まってから確定する（「確認 3」）
- 補足：効果は Google Search Console で見る。ページに計測タグを入れずに使えるので、外部送信なしの方針と両立する

#### US-52 安全のための表記 〔Must〕
- [ ] 紹介ページと設定画面に「眠れない日が続く場合は、医療機関に相談してください」と相談窓口へのリンクを置く（§12）
- [ ] リンク先の候補：厚生労働省「まもろうよ こころ」など。公開前にリンク先が正しいか確かめる（未確認）

#### US-53 研究の紹介 〔Should〕（§13 案D）
- Scullin ら（2018）：寝る前に 5 分、明日やることを書いた人は、その日やったことを書いた人より早く寝付いた、という研究（記憶による要約。公開前に原文で確認する）
- 載せるときの条件
  - [ ] 「書く」研究であり、「声で話す」効果は確かめられていない、と正直に書く
  - [ ] 比べられた側は「その日やったことを書く」＝日記に近い。**日記が寝付きを良くするとは書かない**
  - [ ] 出典（著者・年・掲載誌）を明記し、リンクする

#### US-54 ブレインダンプの解説ページ 〔Could〕
- 「ブレインダンプ」（月 1,200・KD 0）向けに「寝る前のブレインダンプのやり方」を別ページにする案
- 検索する人の多くが仕事術として調べている可能性がある（未確認）。上位ページの顔ぶれを Ahrefs で見てから決める

#### US-55 日記まわりの検索語に合わせた紹介 〔Could〕
- 「音声日記」などの検索数は未確認（2026-10-25 時点で Ahrefs の月の上限に達している。§13）
- 手がかり：「ジャーナリング アプリ」月 600。調べ終えたら、紹介ページの一節にするか別ページにするかを決める

### この線引きにした理由
1. **公開の目玉は「考え事で眠れない夜に、声で預ける」**。検索から来た人が最初の夜に一周できることを最優先にした
2. **日記は最小限だけ入れる**。オーナーが 10-25 に決めた機能で、録音・保存の仕組みを夜のメモと共有するため、追加の手間は小さい見込み（未確認。PM とエンジニアに見積もってもらう）。データを最初から区別しておけば、後で作り直さずに済む
3. **音声方式が未決でも止まらない**。テキスト入力・保存・朝の画面・PWA・紹介ページは方式に関係なく先に作れる（team.md「未決でも止めないものは進める」）
4. **データを失わないことは信頼の土台**。エクスポートと更新時の保持を Must にした

- [ ] iPhone 実機（Safari のタブ／ホーム画面アプリ）で、上の一周ができる
- [ ] 機内モードでも開けて、テキストで預けられる

- [ ] プライバシー表記（US-30）と安全の表記（US-52）がある
- [ ] 「確認 2」「確認 3」に答えが出ている（公開の形と URL に関わるため）

## 5. 「手放すメモ」と「残す日記」の両立（提案）

### 何がぶつかるか
- アプリの約束は「書く・見返すためではなく、**手放すため**」（§1）
- 日記は「**残す**」もの。説明を間違えると「結局ただのメモ帳・日記帳」に見え、紹介ページの約束がぼやける

### 案A：「今日は残す、明日は手放す」 ★おすすめ
時間の向きで分ける。**今日のこと（終わったこと）は日記に残す。明日のこと・気になることは預けて手放す。**

- 夜の流れ：①今日の日記（1 タップでとばせる）→ ②頭の中を預ける → ③おやすみ
- 日記は残り続ける。メモは朝に片付けたら消えていく（アーカイブ）
- 名前は「おやすみメモ」のまま。紹介ページの主役は「考え事で眠れない」。日記は「今日を閉じる」副機能として一節で紹介
- 初めての人（検索から来た人）の最初の夜は、②の「預ける」から始める。日記は朝や初回案内で「使えます」と知らせる
- よい点：「寝る前に 1 日を話す」というオーナーの意図をそのまま生かせる。2 つの役割が言葉で区別できる
- 気になる点：夜の手順が 1 つ増える。とばせること・最初は出さないことで、夜の画面の単純さ（§5-1）を守る

### 案B：「入り口を分ける」
夜の画面は「預ける」の 1 ボタンのまま。日記は別の入り口（夜の画面の小さなリンク、または朝・夕方の画面）から使う別機能にする。

- よい点：夜の画面とコンセプトが一番ぶれない。紹介ページの約束も単純
- 気になる点：日記に気づかれにくい。「寝る前に話す」流れから離れ、オーナーの意図より日記が脇役になる

### おすすめの理由
- 想定ユーザーの夜は「今日の疲れ」と「明日の心配」の両方を抱えている。案A はその 2 つを、別々の置き場所として説明できる
- 研究（US-53）でも、寝付きに効いたのは「明日やること」を書く側で、「その日やったこと」を書く側ではなかった（原文は未確認）。だからこそ日記は「眠るため」ではなく「今日を残すため」と分けて言う方が正直で、案A の説明と合う

## 8. オーナーに確認したいこと

1. **日記とメモの両立は、案A（今日は残す・明日は手放す）で進めてよいですか。** 夜の流れは「①日記（とばせる）→ ②預ける → ③おやすみ」、初めての人の最初の夜は「預ける」から始める、という形を考えています（§5）。案B（入り口を分ける）の方がよければ教えてください。
2. **紹介ページとアプリの関係。** MVP では「紹介ページ → 1 タップで同じサイトの夜の画面」とし、完全な一体型（§13 案F）は見送る案です。iPhone では Safari で使った分がホーム画面アプリに引き継がれないため、引き継ぎはエクスポート → インポート（US-35）で対応します。この形でよければ、インポートを MVP に入れる（Must に上げる）かも決めたいです。
3. **本番の公開先とドメインを、公開前に決めたいです。** 検索の評価は URL に積み上がるため、あとで変えると積み上げが一からになりやすいです。GitHub Pages の `sakakaito.github.io` のままか、独自ドメインを取るか（年ごとの費用がかかり、0 円の目標とぶつかります）を選んでください。
